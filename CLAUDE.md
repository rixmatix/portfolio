## Non-negotiable rules

### Tokens
- Two tiers: **primitives** and **semantic aliases**, both in `tokens.css`.
- Component CSS in `main.css` references **semantic tokens only**. Never use raw hex values, raw px spacing, or primitives in components.
- New values go in `tokens.css` first (primitive, then semantic alias), then get used.
- Both modes share type, spacing, and grid tokens. Only the color layer swaps.

### Modes
- `ds` = dark, design systems focus. **This is the default.**
- `gen` = light, generalist product design focus. Set with `data-mode="gen"` on `<html>`.
- The choice persists in **sessionStorage, not localStorage**, so every new visit opens in DS/dark. The inline `<head>` script on each page must read sessionStorage. Check for any page still reading localStorage.
- Mode-specific content uses the `.mode-ds` / `.mode-gen` wrappers.

### Known bug classes. Check for these on every change.
1. **Prose `ul` capping layout lists.** Global prose rules (`max-width: 68ch`, `padding-left`) quietly constrain any `ul`-based layout component. **Every new `ul`-based component must be added to the prose escape list** in `main.css` (there's a comment marking it). This has bitten the case grid, metrics band, and card trio.
2. **Padding shorthand clobbering.** Never put `padding: X 0` on elements that carry both `.section` and `.container`, because it zeroes horizontal padding below 1280px. Use `padding-block` for sections and `padding-inline` for containers, so the two axes can't overwrite each other.
3. **Full-bleed and sticky.** `.spec-figure--bleed` uses `width: 100vw; margin-left: calc(50% - 50vw)`, with `overflow-x: clip` on `html`. Must be `clip`, **not** `hidden`, or sticky positioning breaks.
4. **Case card corner handles** are one `::after` with layered gradients. Don't reintroduce helper markup.

### Content
- Copy lives in clearly commented blocks: `<!-- ===== COPY: SECTION ===== -->` … `<!-- ===== END COPY ===== -->`. Keep that convention on new pages.
- The header and footer are duplicated on every page. If you change one, change all of them and say so.
- **Never invent metrics, outcomes, client details, or quotes.** If a case study is missing information, leave a visible `[TODO: …]` placeholder and ask Ricky.
- Image paths are relative: `../assets/img/…` from `work/` pages, `assets/img/…` from the root.
- Images below the fold use `loading="lazy"` and have meaningful `alt` text.

### Visual system (reference, don't drift)
- Type: Fraunces (display serif), Inter (body), JetBrains Mono (labels/technical).
- Accent: signal red, `#FF5C49` on dark and `#BE3520` on light, both verified WCAG AA. Re-verify contrast for any new color pairing.
- DS canvas: 72px blueprint grid aligned to the header's bottom edge. Gen canvas: SVG fractal-noise grain at ~0.16 opacity.
- Case study pages: sticky sub-nav with IntersectionObserver scrollspy. Vertical left rail at ≥1100px, horizontal sticky bar below that.
- Footer: collapsible live token readout (reads computed custom properties and updates when the mode changes).

## Case study structure

Each case study: **problem → my role → key decisions / process → outcome / impact**. Build new ones from the patterns in `work/_layout-template.html`; don't invent new layout patterns unless asked. If a new pattern is genuinely needed, add it to the template page too.

## Working agreement

- Before a large change, give a short plan and list the files you'll touch.
- After changes, check both modes and widths of ~375px, ~1024px, ~1280px, and 1440px+. Confirm no horizontal scroll and that all images load.
- Keep the JS small and dependency-free. No external libraries or CDNs besides Google Fonts.
- Don't commit or push unless asked. When asked, use clear commit messages, and never touch `CNAME`.
